// notes — final spec for implementation

B1 .chan-text loses the -webkit-line-clamp: 3. Panel gets a fixed height (matches the network sibling) and scrolls. Scroll style: option A — scrollbar hidden (scrollbar-width: none + ::-webkit-scrollbar{display:none}), top/bottom 14px gradient fades mask the clipped edges so the overflow is hinted visually without a bar.

Same .hide-bar-fade + .fade-wrap treatment also applies to:

  • settlements panel (#settlementsEl)
  • upgrades panel (#upgradesEl)
  • dispatch log (#logEl) — keeps visible scrollbar. Log is the one panel where a real scrollbar aids searchability (scroll-thumb shows position in history), so the fade treatment does NOT apply here.

B2 Overlays are borderless, blend with the panel background.

  • clock — rides the title row, right-aligned beside // route. HH:MM 24h, derived from S.ticks % TICKS_PER_DAY / TICKS_PER_DAY × 24h. No day counter.
  • coord — x:{x} y:{y} — SVG-space integer coordinates from seg.pathFn(S.dotT) (0..400 range).
  • next — → {callsign} {km} — reads S._transient.currentSegment.to + remaining-segment km.
  • coord + next sit in a persistent route-footer strip below the SVG, always visible. This keeps the panel bottom shape consistent whether or not the weather row is shown.

B3 Weather legend row lives below the route-footer. Gated on S.weatherRadio L1+ (existing gate). ☉ gear button restored as toggle. Gradient inverted: low pressure = green (left), high pressure = pink (right). 984 / 1002 / 1020 hPa labels run underneath the bar, hPa aligned with the 1020 number.
